The four proposals are **not yet formally valid as stated**. F-01 needs stronger hypotheses and a corrected Kulisch width formula; F-02 needs a lease protocol beyond CAS; F-03 can provide accelerator-resident ownership but not generally host-free *interprocess* synchronization; and F-04 is valid only after reducing each rotor action to one- or two-qubit unitary blocks.

## F-01 — Lean 4 mechanization

### Stiefel retraction

For real matrices, define:

```lean
import Mathlib.LinearAlgebra.Matrix
import Mathlib.Analysis.Normed.Module.FiniteDimension

open Matrix

def Stiefel (D K : ℕ) := {X : Matrix (Fin D) (Fin K) ℝ // Xᵀ * X = 1}

def IsTangent (X Z : Matrix (Fin D) (Fin K) ℝ) : Prop :=
  Xᵀ * Z + Zᵀ * X = 0
```

A minimal sound theorem signature is:

```lean
theorem cayley_pade_preserves_stiefel
    {D K : ℕ}
    {X Z : Matrix (Fin D) (Fin K) ℝ}
    (hX : Xᵀ * X = 1)
    (hZ : IsTangent X Z)
    (hInv : IsUnit (1 - (1 / 2 : ℝ) • Ω X Z)) :
    (R X Z)ᵀ * R X Z = 1 := by
  sorry
```

This signature is schematic until `Ω` and `R` are defined. The critical missing condition is that the Cayley transform must be generated by a **square skew-symmetric operator** \(A\), not directly by an arbitrary rectangular tangent \(Z\). A standard construction is

\[
A = ZX^{T}-XZ^{T},
\qquad A^{T}=-A,
\]

followed by

\[
Q=(I-\tfrac12 A)^{-1}(I+\tfrac12 A),\qquad R_X(Z)=QX.
\]

The more faithful Lean interface is therefore:

```lean
def skewGenerator
    {D K : ℕ} (X Z : Matrix (Fin D) (Fin K) ℝ) :
    Matrix (Fin D) (Fin D) ℝ :=
  Z * Xᵀ - X * Zᵀ

def cayley
    {D : ℕ} (A : Matrix (Fin D) (Fin D) ℝ) :
    Matrix (Fin D) (Fin D) ℝ :=
  (1 - (1 / 2 : ℝ) • A)⁻¹ * (1 + (1 / 2 : ℝ) • A)

theorem cayley_orthogonal
    {D : ℕ} {A : Matrix (Fin D) (Fin D) ℝ}
    (hskew : Aᵀ = -A)
    (hinv : IsUnit (1 - (1 / 2 : ℝ) • A)) :
    (cayley A)ᵀ * cayley A = 1 := by
  sorry

theorem retraction_stiefel
    {D K : ℕ}
    {X Z : Matrix (Fin D) (Fin K)}
    (hX : Xᵀ * X = 1)
    (hTan : Xᵀ * Z + Zᵀ * X = 0)
    (hinv :
      IsUnit
        (1 - (1 / 2 : ℝ) • skewGenerator X Z)) :
    (cayley (skewGenerator X Z) * X)ᵀ *
      (cayley (skewGenerator X Z) * X) = 1 := by
  sorry
```

For a genuine Padé approximant, the theorem must additionally specify the rational function and prove its orthogonality property. “Cayley–Padé” alone is not a mathematical definition.

### Kulisch accumulator

The proposed bound

\[
W_{\min}=2(e_{\max}-e_{\min})+2p+\lceil\log _2N\rceil
\]

is not generally justified. For exact accumulation of \(N\) products whose aligned signed magnitudes occupy exponent interval \([e_{\min},e_{\max}]\), a sufficient unsigned fixed-point width is typically of the form

\[
W \ge (e_{\max}-e_{\min}) + 2p
       + \lceil\log_2 N\rceil + c,
\]

where \(c\) accounts for sign, guard, and endpoint conventions. A factor of \(2\) on the exponent span is conservative in some encodings but is not the canonical theorem and cannot be asserted without defining the number format.

A minimal parameterized Lean theorem is preferable:

```lean
structure ProductFormat where
  p       : ℕ
  emin    : ℤ
  emax    : ℤ
  horder  : emin ≤ emax

def kulischWidth (f : ProductFormat) (N : ℕ) : ℕ :=
  Int.toNat (f.emax - f.emin) +
  2 * f.p +
  Nat.ceilLog 2 N + 2

theorem kulisch_exact_accumulate
    (f : ProductFormat)
    {N : ℕ} (hN : 0 < N)
    (W : ℕ)
    (hW : kulischWidth f N ≤ W)
    (xs : Fin N → FixedProduct f)
    (hRepresentable : ∀ i, representableInWidth W (xs i))
    :
    exactAccumulator W xs =
      ∑ i, (exactValue (xs i) : ℤ) := by
  sorry
```

The theorem must define overflow absence, subnormal handling, sign representation, exponent alignment, and whether \(N=0\) is permitted. The phrase “zero rounding error prior to final rounding” should be formalized as equality in an exact integer or rational model, not as a floating-point predicate.

**Verdict:** F-01 is salvageable, but neither stated theorem is currently a complete Lean proposition.

## F-02 — RDMA PMTP tensor bus

One-sided RDMA Read/Write plus remote 64-bit CAS does **not by itself guarantee linearizable read-leases**.

CAS gives atomic modification of one remote word under the RNIC’s ordering rules. Linearizable leases additionally require:

- a precisely defined lease state machine;
- acquire, renew, validate, and release operations;
- a monotonic epoch or version;
- protection against stale DMA writes after lease expiry;
- memory-ordering and completion rules;
- a reclamation protocol preventing reuse of an MR while old operations remain in flight;
- failure handling for node, QP, link, and timeout failures.

A safe protocol is closer to seqlock/version validation:

1. CAS epoch from an even unlocked value to an odd ownership value.
2. Publish descriptor and data.
3. Change epoch to an even committed value with an RDMA atomic or ordered write.
4. Reader reads epoch \(e_1\), reads data, then reads epoch \(e_2\).
5. Accept only if \(e_1=e_2\) and the value is committed.
6. Revalidate before lease expiry and before dereferencing the descriptor.

This establishes a linearizable **logical protocol** only if the memory-registration lifetime and RDMA ordering assumptions are proven. It does not establish coherence of arbitrary remote CPU caches, nor does it automatically prevent an old writer from completing after ownership transfer.

**Verdict:** CAS is necessary but insufficient. The design can avoid host IPC on the fast path, but “zero CPU bottleneck” is too strong: RNIC progress, completion polling, registration, failure recovery, and reclamation still consume host or control-plane resources.

## F-03 — CUDA-native residence and leases

The required VMM sequence is:

```text
cuInit
cuDeviceGet
cuCtxCreate / context selection

cuMemGetAllocationGranularity
cuMemCreate
cuMemAddressReserve
cuMemMap
cuMemSetAccess
```

For exported interprocess memory:

```text
cuMemExportToShareableHandle
cuMemImportFromShareableHandle
cuMemAddressReserve
cuMemMap
cuMemSetAccess
```

`cuMemMap` only establishes the virtual-to-physical mapping; it does not make the range accessible. Access permissions must be explicitly installed with `cuMemSetAccess`.[1][2]

For peer GPUs, each device must be included in the access descriptors, and peer capability must be verified. NVLink or PCIe topology alone does not guarantee that a particular allocation is peer-accessible.

A device-resident lease word can be manipulated by GPU atomics:

```cuda
unsigned long long old = atomicCAS(
    lease_epoch,
    expected_epoch,
    desired_epoch);
```

However, the CUDA memory model does not turn this into a distributed transactional lease automatically. Correctness requires:

- release/acquire-compatible atomic operations;
- an explicit publication protocol for descriptor and payload;
- stream/event synchronization where required;
- no unmapping or freeing until all kernels and peer accesses have completed;
- proof that the target devices support the required atomics and peer memory semantics.

The VMM APIs control mapping and access permissions, not application-level ownership. Also, shareable handles establish allocation sharing, not universal host-free synchronization. The documented API distinction between allocation, mapping, and accessibility is explicit.[1][3]

**Verdict:** GPU-resident leases are feasible within a controlled CUDA context and supported peer topology. They are not automatically host-free across processes or devices. Use device atomics for the protocol, but use CUDA events, stream synchronization, or an equivalent completion mechanism for lifetime and visibility boundaries.

## F-04 — Clifford rotor scaling

For a simple bivector rotor

\[
R=\cos(\theta/2)-\sin(\theta/2)e_{ij},
\]

the corresponding spin representation is a single-qubit \(Z\)-rotation up to convention and global phase:

\[
R_z(\theta)=
\begin{pmatrix}
e^{-i\theta/2}&0\\
0&e^{i\theta/2}
\end{pmatrix}.
\]

The OpenQASM 2.0 mapping is:

```qasm
OPENQASM 2.0;
include "qelib1.inc";

qreg q[1];
creg c[1];

rz(theta) q[0];
```

For Clifford+T output, replace `rz(theta)` with the Ross–Selinger synthesized sequence:

```qasm
OPENQASM 2.0;
include "qelib1.inc";

qreg q[1];
creg c[1];

// Generated Clifford+T approximation:
// H, S, T, and their inverses as required
h q[0];
t q[0];
s q[0];
t q[0];
```

The actual sequence must be generated by the exact grid solver; the illustrative sequence is not an approximation certificate.

Ross–Selinger synthesis applies to single-qubit \(Z\)-rotations and produces approximation quality controlled by an algebraic grid over \(\mathbb Z[1/\sqrt2,i]\). The practical T-count is approximately

\[
4\log_2(1/\varepsilon)+O(\log\log(1/\varepsilon)),
\]

rather than merely an unspecified \(O(\log(1/\varepsilon))\) claim.[9] The Clifford+T group is dense, and T-count is the usual non-Clifford cost measure.[6]

For a general \(Cl(p,q)\) rotor:

- decompose the spinor action into orthogonal-plane rotations;
- map each plane rotation to a one- or two-qubit unitary;
- synthesize each block;
- account for basis changes, entangling gates, and compilation overhead.

A state-dependent test

\[
F_\psi=|\langle\psi|U^\dagger V|\psi\rangle|^2
\]

is insufficient as a circuit-equivalence certificate because it can hide errors on orthogonal states. Use operator fidelity or diamond/operator norm bounds, for example

\[
\|U-e^{i\phi}V\|_{\mathrm{op}}\le\varepsilon.
\]

If the specification requires \(F_\psi\ge1-\varepsilon\) for every normalized \(\psi\), that condition must be quantified universally.

**Verdict:** Ross–Selinger gives the claimed logarithmic asymptotic for single-qubit rotation synthesis, with a practical leading constant near \(4\). It does not directly solve arbitrary high-dimensional Clifford rotor compilation. The high-dimensional design is valid only after an explicit rotor-to-qubit decomposition and a global error-composition proof.
